# GRW ScriptHook 魔改版（Beta1.0）

《幽灵行动：荒野》（Ghost Recon Wildlands）的
ScriptHookV 同类框架。以 `dinput8.dll` 代理形式随游戏加载，暴露
C ABI，并按 ASI 插件约定加载 `plugins\` 下的 `.asi` 插件。

> 本项目为原版 **grw-scripthook** 的中文魔改版，在原版框架之上
> 重做了游戏内菜单、中文本地化，并新增了多项实用功能。

## 这是什么

原版是作者反编译《幽灵行动：荒野》逐步定位得到的引擎扩展框架。  
游戏本身没有脚本层、没有控制台、没有可直接使用的API，因此框架的每一项能力都源于游戏引擎中一段被定位并验证过的函数或字段。

魔改版在保留全部底层能力（载具、实体、相机、事件、原生UI 等）的前提下，重点改进了**F4 模组菜单**。  
改为独立的 D3D11/ImGui 覆盖层渲染（原生支持中文字体），并把菜单文案接入独立的 `lang.ini`：**中英内置、切换即时生效**，也可高度自定义汉化。

## 魔改内容一览

自魔改分支以来的主要变更（按功能归类，详见 Git 提交）：

- **菜单渲染重构**：用 D3D11 + Dear ImGui 覆盖层重绘 F4 菜单，内置 CJK 字体，中文显示不再依赖原生 UI。
- **插件源码与配置约定规范化**：源码按插件分目录放在仓库的 `plugins\<插件名>\`（`.c`、插件自己的 `.ini`、文案 `lang.ini` 同目录同名），构建后按同样的结构落到游戏目录。
- **完整中文本地化**：中英编译内置、切换即时生效；文案放在 `lang.ini`（框架一份、每个插件一份），第三方插件的菜单也能**不改它的代码**翻译。
- **菜单体验改进**：根菜单顺序可在游戏内调整（「ScriptHook 设置 → 菜单排序」，每行一项、← → 上移/下移一位，改完立即存盘并当场生效），也可直接编辑 `[MenuOrder]`；**根菜单里每一页都能排**，`ScriptHook 设置` 与 `Forge 资源侧载` 只是默认排第 1、第 2（权重 0 与 10，只在键缺失时补写，之后随便挪）。页面提示走 `<页面键>.hint`，导航与交互一并优化。
- **ScriptHook 设置（内置首行页）**：顶层是「加载插件（总开关）」＋子页「各插件开关」「CPU 调度控制」与「菜单排序」，最后一行是菜单语言；插件总开关就放在页面上（原先单独的「加载设置」页已移除），CPU 的核数与优先级仍独立成一页。**插件一律默认关闭（内置与第三方相同）**：只有在 `scripthook.ini` 的 `[plugins]` 里写 `名字=1`，或在「各插件开关」页打开，才会被加载；没有对应行的插件会在首次扫描时被自动补一行 `=0`（于是那张表最终列全每个插件目录及其状态）。**删掉 `scripthook.ini` 就是把所有插件重置为关闭**（排障用；注意它同时会把 `[loader]` 的 CPU 档位、语言与翻译表一并回默认）。
- **CPU 核心调度（按启动阶段分别设置）**：为游戏启动的三个阶段各设一档 —— 三个阶段是**依次走过、不会回头**的三步（同一次游戏里各进入一次）：**Logo 阶段**（启动窗口出现 → 游戏主窗口出现：此阶段禁超线程可让 logo 秒进）、**窗口加载阶段**（主窗口出现 → 进主菜单，即第一次加载，引擎自己还在忙：部分机器禁小核可秒进，部分机器如被 Win11 自动优化过则需"全部核心(强制)"）、**游戏中**（**首次进主菜单之后的一切都算** —— 主菜单、大厅、之后的加载界面、暂停菜单、世界，直到退出游戏：禁超线程 / 禁 CPU0 缓解间歇性卡顿）。每档可选：不干涉（什么都不设置，含系统自动优化）/ 全部核心(强制) / 禁超线程 / 禁小核（仅 Intel 12代+ 大小核，其它平台不适用且不做改动）/ 及其组合（游玩档另有禁 CPU0 的组合）。另有**优先级**：游玩阶段一个档位（**不干涉 / 正常 / 高于正常 / 高**），外加 **Logo 与窗口加载共用的一个开关**「加载阶段使用效率模式」（**默认关**）。开关打开时，那两个阶段保持 Win11 的 EcoQoS（任务管理器里那一列「效率模式」，它**不是**优先级类）：让调度器优先用能效核、允许降频；**它只在 Win11 上有效** —— 接口在更早的系统上存在，但这一级本身是 Win11 才有的（Win10 只会把进程标成 LowQoS），所以 Win10 及更早系统上打开这个开关时，会**改为保持「低」优先级类**代替（"加载时把机器让出去"的同一个意思，用本机真有的手段做），日志与设置页提示行都会写明；并且**进入"游戏中"阶段时一定会把加载阶段开过的那份关掉、还原成我们介入前的状态**，而进程启动前就被外部开启（任务管理器勾选、Process Lasso 等）的我们一律不动；不提供"实时"，以免拖累系统输入与音频）与"游玩时最大核心数"上限（**只作用于游玩阶段**，启动阶段不做限制，避免影响启动）。除让引擎按当前阶段的核数自居外，还会真实设置游戏进程的亲和性与优先级（任务管理器「设置相关性」可见），并在游戏启动时自己改优先级的情况下保持住所设档位。
- **载具与生成优化**：载具菜单汉化、生成载具时缓存预热，优化首次召唤载具的生成速度，且世界重载后不重复预热。
- **跳过开场视频（一次性）**：内置自写的 skipintro 插件，只跳过启动时的 **4 个片名** —— `videos\Nvidia.bk2`、`videos\Ubisoft_Logo.bk2`（片头 logo）与 `videos\TRC\<语言>\Epilepsy.bk2`、`WarningSaving.bk2`（光敏/存档警示）。做法是对 GRW.exe 导入表里 `GetFileAttributesA/W`、`CreateFileA/W` 四个槽位回答"文件不存在"（**不动任何游戏文件**，验证完整性也不会回滚）。实测引擎只在启动时**一次性集中探测**这些片名（15 个会话里都是同一毫秒一批，之后整局再无探测），所以插件在**已启用开关覆盖的片名全部拦到**（两组都开=4/4，只开一组=2/2）**或进过一次主菜单**（保底）之后，就把四个 IAT 槽位**原样写回并停止拦截** —— 本局后续零开销、零副作用。释放后菜单状态行写明"已释放"，此时再改开关只对下次启动生效；两个开关都为 0 时不装任何补丁。
- **插件模式黑名单（统一 API，协作式）**：插件在源码里声明自己**不允许运行的条件**（战役 / 幽灵模式(魅影) / 雇佣兵 / 游击战 / Ghost War 位掩码）。命中时框架把该插件的**模组菜单入口整行隐藏**（子页不可进入，若正停在该页会自动退回上级），并在"ScriptHook 设置 → 各插件开关"页写明是被哪些条件禁掉的；同时通过查询 API 与回调**通知插件自己停下来** —— 停止插件代码是插件的事（插件各自带线程与 MinHook，框架不接管其钩子，这条边界在文档与头注释里写明）。**没有声明的插件（含全部第三方插件）默认在 Ghost War 与雇佣兵下被禁**，只有主动声明"无"（`SH_MODE_BLACKLIST_NONE`）才是全部放行；框架内置页（ScriptHook 设置 / Forge 等）不受影响（中文聊天输入自 2026-09 起已改为插件 `cnchat`，因此它也受这套规则约束）。条件只有五种模式：曾有一档"主菜单"（前端未选任何东西），实测其判据（GameFlow slot 16 为空）是**锁存**的 —— 从战役退回主菜单后不再成立、插件会重新出现，因此**已按实测移除**，宁可少一档也不做"时对时错"的判定。示例插件 `blacklist_sample` 演示完整写法（声明 + 回调 + 每次干活前查询 + HUD 计数），详见 [`docs/plugin-blacklist.md`](docs/plugin-blacklist.md)。
- **文件 API 拦截层（唯一所有者 + 公共 API）**：文件相关的 kernel32 调用由框架**唯一一套内联钩子**接管（全进程生效，含通过 `GetProcAddress` 拿到的函数指针），其余模块只登记**规则**：**隐藏**（回答"文件不存在"）/ **重定向**（换成另一个路径继续调用）/ **自定义决定**（回调自己作答或放行），另有**只读观察**与**事后回调**（可改写读到的数据，供内容替换）。多条规则命中同一次调用时裁决为 **隐藏 > 重定向 > 决定**，同级按登记顺序；多个"决定者"按登记顺序**依次询问**（只观察的规则不会吞掉别人的决定）。**首条规则登记才装钩子**、只装被需要的目标，**最后一条注销即整套下线**（零钩子、零 trampoline），`skipintro` 的"拦满即释放"由此原生保留；规则表 32 条、槽位复用、登记失败明确记日志。原先五套各自为政的实现（`skipintro` 手写导入表补丁、`GhostNoWipe`/`GhostWipeProbe`/`forgeprobe`/`forge_io` 各自的 MinHook）全部改为登记者，"一个目标只能一个钩子"造成的互斥（`CreateFileW`、`MoveFileExW`）从此消失；`forge_io` 也因此不再需要用 `GetFinalPathNameByHandleW` 事后反查句柄。示例插件 `file_watch_sample` 演示观察者、隐藏规则与查询接口，详见 [`docs/file-interception.md`](docs/file-interception.md)。
- **插件自绘 UI 公共 API**：框架把「画界面」做成一套 **C ABI** 的公共绘制 API（`@defgroup draw`），任何插件都能注册一个每帧回调（`ShDrawAdd`），在自己的窗口里用一组原语（文字 / 面板 / 按钮 / 开关 / 数字 / 滑块 / 下拉 / 提示行 / **输入框**）画自己的界面，**与 F4 菜单同一套字体、配色与分辨率缩放**。原语实现是 ImGui（在 overlay 里），但 **ImGui 不进插件 ABI**：插件是普通 C DLL，链接或 `GetProcAddress` 都行；MinGW 链没有 overlay，此时**所有原语是安全的空操作**（`ShDrawReady()` 返回 0），同一份插件源码两条链都能用。回调跑在**渲染线程**、每帧一次、在 `Present` 路径上（不得阻塞）；没人注册时零开销；最多 16 个 drawer，满员明确记日志。**输入框的职责切分是刻意的**：框架负责外观、焦点、组合串、候选列表、候选窗锚点（按被聚焦控件矩形自动定位）、并**收集字符**（游戏窗口是系统输入法唯一的成字通道）；**插件负责自己的文本缓冲与热键/提交** —— 框架从不编辑一个字节，也从不解释一个命令键，一个字节只有一个写者。示例插件 `draw_sample`（窗口 + 无边框角落读数 + 输入框）演示全部原语；**框架原来的中文聊天输入框也已改为插件 `cnchat`**（框架内不再有任何聊天代码），它的盒子就是一个 frameless drawer 调 `ShDrawInputBox`，所以"框架自己的盒子"与"插件的盒子"是同一段绘制代码，详见 [`docs/ui-drawing.md`](docs/ui-drawing.md)。
- **「最后的仪式」闪退修复（LastRites_dlcfix 插件）**：进入该新 DLC 加载中闪退，是游戏自身缺陷——锁区版里 Uplay 对该**免费更新**的授权查询返回「未获得」，游戏随后在加载流程中走了一条解引用空指针的分支（实测固定崩在 `GRW.exe+0xE09DA51`，读 `null+0x340`）。插件在游戏取该授权函数指针的地方（`kernel32!GetProcAddress`）拦下它，**只对实测确认的那一个条目 `3718`** 按「已获得」处理，其余条目（含全部付费 DLC）一律返回游戏原本得到的答案；该条目号**写死在代码里、不可配置**，以免被改指向付费内容。菜单里只有一个开关（**默认关**），关闭时**不安装任何钩子**，游戏行为与未装本插件完全一致；**改动于下次启动游戏时生效**（游戏在启动时读取并缓存授权结果）。**仅限单机使用**（游戏含 EasyAntiCheat）；与社区补丁（Koaloader 代理 + 第三方解锁器）**不要同时启用**；官方修复推送后请关闭开关并删除 `plugins\LastRites_dlcfix`。
- **魅影模式不删档（GhostNoWipe 插件）**：魅影模式中完全死亡（暴毙，或倒地未救起流血致死）后，游戏会提示失败并删除该存档。经**两轮文件操作探针取证 + 替换验证**确认，删档由**两处记录**构成：一是把 `N.save` 改名成 `N.save.delete` 并写入一份 `.delete`（**这个 `.delete` 本身就是存档界面读取的"已删除"记录之一**，不是临时残留）；二是在改名之前，**游戏已经把"本局结束"写进了 `N.save` 自己的内容里**——实测这次写入发生在死亡画面后约 10 秒、**比改名早约 19 秒**（替换验证：放回死亡前的存档文件，档就正常列出；放死亡那一刻写入的那份，档就不列出）。**两处任一留痕即被判为已删**，因此插件三处同时守住：① **存档写入（`.tmp` 就位）时即用干净副本换回**，内容始终停在你活着时的最后一次存档；② **改名一律丢弃且不留下任何替代文件**；③ **对 `.delete` 的写入改道到插件自己的 `temp\` 目录**（不再使用 `%TEMP%`，随插件一同卸载）。最终做到**磁盘上不残留任何删档痕迹、存档内容也不被改写**，进度退回最近存档点。回到存档界面时游戏内存里仍认为该档已删（**这一步发生在进程内**：探针实测此刻游戏不再读取任何存档文件，判定来自内存，故无法也不需要拦），**同一时刻屏幕上方会常驻一条状态提示**，说明存档已保住、重启后继续，**直到你重新进入游戏才自动收起**；**重启游戏重新扫描目录后该档即恢复显示并可继续游玩**。仅**魅影档**受保护（由死亡画面这一行为特征识别，并持久化到 `ghost_slots.ini`），普通档的存档与删除操作完全不受影响。菜单只有一个开关（**默认开**）；关闭时**不安装任何钩子、不写日志**，游戏行为与未装本插件完全一致。**注意**：在界面里手动删除魅影档走的是同一套流程，同样会被拦下 —— 确实要删档时，请先在菜单或 `plugins\GhostNoWipe\GhostNoWipe.ini` 里关闭插件。**仅限单机使用**（游戏含 EasyAntiCheat）；开启云同步时本地保留的存档可能与云端状态冲突，需自行取舍；官方修复推送后请关闭开关并删除 `plugins\GhostNoWipe`。

## 安装

1. 将 `dinput8.dll`、`plugins\`、`scripthook.ini` 放入游戏根目录（与 `GRW.exe` 同级）。
2. 各种插件放入对应的路径 `plugins\<插件名>\<插件名>.asi`（每个插件一个文件夹）。

```
Tom Clancy's Ghost Recon Wildlands/
├── GRW.exe
├── dinput8.dll
├── scripthook.ini     主配置文件
├── logs/              运行日志
├── mods/              Forge Mod Loader 的 mod 目录（可选，见下）
└── plugins/           插件目录（每个插件一个子文件夹）
```

## 主配置文件（scripthook.ini）说明

```ini
[loader]
load_plugins=1          ; 0 = 启动时不加载任何插件
cpu_boot=0              ; Logo 阶段：        0=不干涉 1=全部核心(强制) 2=禁超线程 3=禁小核 4=禁超线程+小核
cpu_window=0            ; 游戏窗口加载阶段：同上（例：解 logo 卡用 2；解窗口无限加载用 3 或 1）
cpu_eco_boot=0          ; 加载阶段(Logo+窗口加载)用效率模式：0=关(默认) 1=开；本机不支持时改用"低"优先级
cpu_play=0              ; 游玩阶段：        附加 5=仅禁CPU0 6=禁超线程+CPU0 7=禁小核+CPU0 8=三者全禁
cpu_prio_play=0         ; 游玩阶段优先级：  0=不干涉 1=正常 2=高于正常 3=高
cpu_cores=0             ; 游玩阶段最大逻辑核心数（0 = 不限制；启动阶段不做限制）

[plugins]
chaos=0                 ; 每个插件一行：1 = 加载；0 或"没有这一行" = 不加载
                        ; 首次扫描会把缺行的插件自动补成 =0；删掉本文件可把插件全部重置为关闭

[forgemod]
enabled=0               ; Forge Mod Loader：1 = 加载 mods\（默认关）
dry_run=0               ; 1 = 只解析并写日志，不实际叠加
report_copies=1         ; 1 = 检测同一资源在其它归档里的副本并提示
apply_all_copies=0      ; 1 = 把 mod 自动叠加到那些副本
probe=0                 ; 1 = 安装取证探针（排查用）
log_reads=0             ; 1 = 记录每次读取（排查用）

[Settings]
Languages=zh_cn,en      ; 设置菜单中可选的语言列表（逗号分隔）
Language=zh_cn          ; 当前菜单语言
```

## Forge Mod Loader（游戏资源侧载热替换）

把 `mods\` 目录下的松散文件**侧载**到已有的 `.forge` 条目上：**不解包、不重打包、
不改动原版归档、不写盘**。原理与 FusionFix ModLoader 一致——不是替换文件，而是
在引擎读取的那一刻把被替换的字节区间换成 mod 的内容。

**开启**：在游戏根目录建 `mods\`，并在 `scripthook.ini` 里设 `[forgemod] enabled=1`
（默认关）。F4 菜单里的「Forge 资源侧载」页有开关与状态行。

```
mods/<归档名>/<文件>                  扁平布局，优先级最高
mods/<mod名>/<归档名>/<文件>          按 mod 文件夹名升序，先者优先
mods/~<名字>/...                      "~" 前缀 = 该 mod 被禁用
.../<序号>_-_<条目名>.data            文件名里的序号指定条目
```

**两条硬性约束**（务必先读）：

1. **替换内容必须 ≤ 原条目长度**。该容器里 payload 是紧挨着存放的（没有空隙），
   所以「可用空间」就等于原长度；更大的替换需要移动其它条目，本版本不做，会被
   拒绝并写入日志。
2. **只替换已有条目**，不新增、不删除。`.delete` 后缀会被识别但暂不执行。

**同一资源常存在于多个归档**（例如 `W_ASR_AK47_body_LOD0` 同时存在于
`DataPC.forge`、`DataPC_patch_01.forge` 及 DLC 归档）。只改一份可能被另一份遮蔽，
看起来像「mod 没生效」。loader 会**按 FileDataID 跨归档检索**并把其它副本写进
日志；`apply_all_copies=1` 可自动一并覆盖。改动应优先打到 `*_patch_01`（它胜过其
base 家族）；外观类 3D 模型多位于 `DataPC_GRN_WorldMap*`。

**做 mod**：用 WildlandsToolkit 的 `wlcli` 导出条目（`wlcli entry <forge> <index> <out>`）
→ 修改 → 放回 `mods\<归档名>\`。完整说明、归档角色对照表与实测结论见
[`docs/forge-mod-loader.md`](docs/forge-mod-loader.md)。

### 插件菜单的多语言（`lang.ini` 用法示例）

菜单里的**每一段文本都是一个键**，显示前按四层顺序查找：

```
① plugins\<插件名>\lang.ini   当前语言      ← 该插件的文案
② <gamedir>\lang.ini          当前语言      ← 框架自己的文案（也是共享覆盖层）
③ 编译期基线                  当前语言      ← 编译进 dinput8.dll / 各插件的表
④ 编译期基线                  en-US
⑤ ID 可读化 + logs\scripthook_text.log 记一条缺失
```

键有两种写法，按 `@` 前缀机械区分：

| 键 | 含义 |
|---|---|
| `@fp.hidehead` | **稳定 ID**。改页面标题、改行文案都不会打穿译文 |
| `Hide head` | **字面量**（英文原文）。给**没有源码、无法改代码的第三方插件**用 |

**中英两种语言都编译在程序里**：删掉任何 `lang.ini`，菜单照样能切中英。`lang.ini` 只用来**改**文案或**加**语言，不是"能显示中文"的前提。

`lang.ini` 与配置彻底分离：`*.ini` 是设置（程序会写），`lang.ini` 是文案（**程序只读、永不回写**）。所以删 `scripthook.ini` 只重置设置，文案一条不动。

以 firstperson 为例 —— `plugins\firstperson\lang.ini`：

```ini
[zh-CN]
"@fp.page"           = 第一人称
"@fp.page.hint"      = W/S 选择，回车确认，Esc 返回
"@fp.hidehead"       = 隐藏头部
```

而 ID 与英文同处，写在插件自己的 `.c` 里（每语言一张表，加语言 = 加一张表 + 一行注册）：

```c
static const ShText kEn[] = {
    { "@fp.page",      "First person" },
    { "@fp.page.hint", "W/S select, Enter confirm, Esc back" },
    { "@fp.hidehead",  "Hide head" },
};
ShLangDeclare("firstperson", "en-US", kEn, 3);      /* 中文再来一张表 */

ShMenuCreate("@fp.page");                           /* 根菜单那一行 = 页面标题键 */
ShMenuToggle(page, "@fp.hidehead", 1, NULL, NULL);
```

**第三方插件（没有源码）同样能汉化**——它代码里的字面量本身就是键，只要在它的目录里放一份 `lang.ini`，它的 `.asi` 一个字节都不用改：

```ini
; plugins\Time&Weather\lang.ini
[zh-CN]
"Time & Weather"      = 时间与天气
"Time & Weather.hint" = W/S 选择，回车确认，Esc 返回
```

几条固定约定：

| 键 | 用途 |
|---|---|
| `<页面键>` | 页面标题，同时就是根菜单上那一行 |
| `<页面键>.hint` | 该页面的顶部提示（插件自己没调 `ShMenuHint` 时用它） |
| 其它 ID / 字面量 | 行标签、状态行模板、toast、自绘文本 |

页面**排序**（`[MenuOrder]`）也用同一个页面键，例如 `[MenuOrder]` 里写 `"@fp.page" = 10`；改页面名不再需要搬任何译文。语言**切换后立即生效**，不必重启。排序也可以不改文件：F4 →「ScriptHook 设置 → 菜单排序」，每行一项，按 ← → 上移/下移一位，改动立即写回 `[MenuOrder]`（按 0/10/20… 整段重写）并当场影响根菜单。**所有根页都能排**——`ScriptHook 设置` 与 `Forge 资源侧载` 只是**默认**排第 1、第 2（权重 0 与 10，只在键缺失时补写一次，之后挪动不会被写回）；被关掉或被当前模式禁用的页不在根菜单里，因而不参与排序、也保留它原来的权重。

## 构建

- **Windows（MSVC）**：`pwsh ./build_msvc.ps1`
- **Linux / Proton（MinGW）**：`make`

构建后输出 `dinput8.dll` 到游戏根目录，插件到游戏目录的 `plugins\<name>\<name>.asi`。
源码在仓库的 `plugins\<name>\`（一个插件一个目录），**仓库里的目录结构与部署后的完全一致**：`<name>.c`、插件自己的 `<name>.ini`、文案 `lang.ini`。
