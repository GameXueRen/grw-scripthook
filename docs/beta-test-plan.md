# 首个公测版 · 换机测试说明（1.0-beta1）

> 这份是**给测试者**的：装什么、按什么顺序验、看到什么算通过、出问题收什么信息。
> 同包里的 `README.md` 是给玩家看的（安装/卸载/回滚/配置说明），两者不冲突。
> `docs/beta-audit-first-public-beta.md` 是**内部审计报告**，别转给玩家。

## 0. 一句话流程

复制三个东西到游戏根目录 → 确认三个前提（版本一致 / 杀软白名单 / 单机）→ 启动看日志 →
进游戏按 `F4` → 按第 3 节的清单逐项点一遍 → 有问题就把 `logs\` 整个打包发回。

时间预算：冒烟 5 分钟，八个插件全过一遍约 30 分钟。

## 1. 装什么、放哪儿

把包里下列内容复制到**游戏根目录**（与 `GRW.exe` 同级）：

```

scripthook.ini               框架配置（已按本包 8 个插件写好 [plugins]；[forgemod] enabled=1 跟随开发机）
plugins\                     8 个插件，每个一个子文件夹

lang.example.ini             语言覆盖层参考模板（放着不用管）
LICENSE · THIRD-PARTY-NOTICES.txt
README.md                    框架功能与用法说明（同目录另有 README.txt 纯文本版）
docs\                        测试说明与内部审计报告（★ 本测试套件带；玩家版不带）
                             —— 每份都同时提供 .md 与 .txt；用记事本直接打开 .txt 即可
```

装完应该长这样：

## 2. 开测前的三个前提（能省掉九成「什么都没生效」）

### 2.1 游戏版本必须与开发机一致 ★ 最重要

框架里所有地址都是按开发机那份 `GRW.exe` 钉的。**版本不一致时，功能不会「部分工作」，而是基本全废。**

判据（启动一次后看日志）：`logs\` 里若出现下列字样，说明版本不匹配 —— 别继续测功能，直接把 `logs\` 发回来即可：

```
is not readable          （某处地址读不到，通常是常量过期）
stale constant?          （代码对不上，明确写了常量过期）
wanted 48 89 5C          （同上，括号里会给出实际字节）
MISMATCH                 （版本/指纹不一致）
```

**最快、最确定的判据是直接比指纹**（这一版框架是按 **UPlay 版**游戏钉的；Steam 版的 `GRW.exe` 与它不同）：

```powershell
# 在游戏根目录执行
(Get-Item '.\GRW.exe').Length
(Get-FileHash '.\GRW.exe' -Algorithm SHA256).Hash
```

开发机（也就是 `1.0-beta1` 所依据的那一份）：

| 项 | 值 |
|---|---|
| 大小 | `405,703,672` 字节（约 387 MB）|
| SHA-256 | `1284E4D5AAD5F1CA5D2832B6C46707B1D043205E929B5810FFE1CAF61CBDF751` |
| 文件日期 | 2026-09-15 23:43:55（UPlay 版，2026-09 游戏更新之后）|

> 这份 `GRW.exe` **没有版本资源**（`FileVersion` 为空），所以「体积 + SHA-256」就是它的版本号。
> 两者任一不符 → 先别测功能，把指纹和 `logs\` 一起发回来即可。

### 2.2 杀软白名单

`dinput8.dll` 是「代理 DLL + 挂钩」，Defender 之类的启发式规则很容易直接隔离它。
**先解压/复制之前，把游戏根目录加进白名单。**

怎么判断被隔离了：复制完 `dinput8.dll` 不见了；或游戏能开、但 `logs\` 里**什么文件都没有**（这说明 DLL 根本没被加载）。

### 2.3 只测单机

不要在有其他玩家的模式里带插件跑。插件已声明「幽灵战 / 雇佣兵」黑名单（框架会自动隐藏这些页），但测试阶段按单机来最省事。

## 3. 五分钟冒烟（装完先做这一步）

| # | 操作 | 通过的样子 |
|---|---|---|
| 1 | 启动游戏，等进到主菜单 | 游戏正常进入，**没有**弹窗、没有卡在片头 |
| 2 | 打开 `logs\scripthook.log` | 头两行是 `GRW ScriptHook 1.0-beta1` / `built <日期> <时间>` |
| 3 | 同一文件里搜 `loading plugin:` | **正好 8 行**，且每行下面跟一行 `loaded at ...` |
| 4 | 同一文件里搜 `no ... .asi` 或 `no plugin folders` | **一行都没有**（有就说明文件没放全） |
| 5 | 进游戏（进战役），按 **`F4`** | 出现模组菜单；左侧应有 8 个插件页 + `ScriptHook 设置` + `Forge资源侧载（实验功能）` |
| 6 | 菜单最后一行切一次语言（中文 ↔ English） | **即时**全菜单换语言，不需要重启 |
| 7 | 进 `Forge资源侧载（实验功能）` 页（本套件带 `mods\`） | 页面上显示已启用、能看到已加载的 mod；`logs\` 里与 Forge 相关的行**没有** `refused`（拒绝替换）字样 |

> 菜单缩放：如果这台机器的分辨率 / 显示器让菜单过大过小，可在 `scripthook.ini` 的 `[Settings]` 里加
> `MenuScale=1.2`（0 = 自动按分辨率缩放，默认就是自动）。UI 是自绘覆盖层，不吃系统 DPI 缩放。

## 4. 八个插件逐项

每项都按「怎么测 → 期望」写；结果填到第 9 节的表里。

| 插件 | 菜单页 | 怎么测 | 期望 |
|---|---|---|---|
| **skipintro** | 跳过片头 | 装好后**重启一次游戏**，注意看片头 | 四个片名（Nvidia / Ubisoft logo、光敏警示、存档警示）被跳过；进主菜单后状态行显示「已释放」 |
| **spawner** | 载具生成 | 生成一辆车 → 开一会儿 → 用「撤销」消掉 | 载具出现在附近；能上能开；撤销后消失。**顺带记录**：面朝北召唤时，车出现在**正前**还是**正右**（这是待确认项，见第 5 节）|
| **firstperson** | 第一人称 | 用热键切第一人称 → 走路、上车、开镜 | 视角进入第一人称；头部不遮挡；退出后视角正常 |
| **fov_changer** | 视野 | 拖「垂直视野」滑块 → 再点「恢复默认」 | 视野随之变化；恢复后回到游戏默认 |
| **cnchat** | 中文聊天 | 先在 `plugins\cnchat\cnchat.ini` 里打开开关 → 重启 → 游戏内按 `T` → 打中文 → `Enter` | 出现自绘输入框，能打中文（候选窗正常），回车后文字进游戏聊天框，`Esc` 取消 |

| **OpticalCamo** | 光学迷彩 | 打开总开关 → 调「敌人视觉感知」档位（0.1x–0.9x）→ 到敌人附近 | 敌人感知明显变弱；关掉后恢复正常（关时会主动交还，线程 park） |

> `cnchat` 与 `OpticalCamo` **默认关闭**是设计（前者要在自己的 ini 里开，后者在菜单里开），不算故障。

### 4.1 Forge资源侧载（实验功能 · 框架功能，本套件带 `mods\`）

## 6. 已知的、不算 bug 的现象（避免误报）

1. **`logs\` 每次启动会被清空**（除了崩溃日志 `scripthook_crash.log`，它是追加的）—— 设计如此。
2. **崩掉的那一局**：崩溃报告写在 `logs\scripthook_crash.log`，内容只有模块名+偏移与基址，**不含你的用户名、机器名或完整安装路径**，可以放心发回来。
3. **`插件开关` 页里会出现你不认识的插件名**：框架会扫描 `plugins\` 下每个文件夹，并把缺行的自动补成 `=0`（列出了但其实没装、或不加载）。正常现象。
4. **幽灵战 / 雇佣兵模式下部分插件页自动消失**：这是插件自己声明的黑名单，设计如此。
5. **`ammo_capacity` 的 `lang.ini` 是空的注释模板**：它的文案编译在插件里，功能正常；那份文件只是留给「就地覆盖文案」用的。
6. **分辨率 / DPI**：UI 按 backbuffer 自动缩放，系统 DPI 缩放不影响；不合适就用 `MenuScale` 微调（见第 3 节）。
7. **`NPCSpawner` 不在本包里**：它功能只完成一半（生成的 NPC 不主动攻击），已按决定移出公测集，源码保留在仓库。
8. **Forge 在两个 PvP 模式下不看 mod**：幽灵战 / 雇佣兵下 `mods\` 一律不被服务（有意为之，日志会写 `mode gate: …`）。
9. **`mods\README.txt` 不参与替换**：Forge **只看文件夹、不看文件**，那份说明留着就行。
10. **`docs\` 只在测试套件里**：玩家版不带（内部资料）；`mods\` 则是**两个包都带**（Forge 侧载的测试资源，逐字节原样，不测就不加载）。
11. **模组菜单里没有鼠标指针**：本版有意**完全不碰**系统指针（菜单本来就靠键盘：`F4` / `↑↓` / `←→` / `Enter` / `ESC`），游戏自己的地图与暂停界面里指针照旧。
12. **本套件自带 `LogLevel=debug`**：包内 `scripthook.ini` 的 `[Settings]` 由打包脚本写入这一行，所以 `logs\` 里各模块日志齐全（下面各条的「看哪里」都依赖它）。**玩家包不带这一行**，走发布版默认 `warn`：框架的模块日志不生成，`logs\` 里是 `scripthook.log`、崩溃报告（若有）与各插件自己的日志。你要临时改级别，就改这一行再重启一次 —— 想照玩家包的形态看一眼，把这一行改成 `warn` 重启即可。

## 7. 出问题时怎么收集信息（很重要）

**默认就把这些发回来即可：**

1. 整个 `logs\` 目录（压缩成一个 zip）。
2. 这台机器上：游戏版本（`GRW.exe` 的属性 → 详细信息）、Windows 版本、显卡型号。
3. 出问题的那一刻你在做什么（哪个插件页、点了什么）。

**如果是崩溃：**

1. `logs\scripthook_crash.log` 最后一段（含 `=== GRW ScriptHook ...` 那一行起）。
2. 崩溃时是否开着别的覆盖层（MSI Afterburner / ReShade / 录屏等）。
3. 是否稳定复现，步骤越具体越好。

**如果「什么都没生效」（菜单按不出来）：**

1. 先确认 `dinput8.dll` 还在（防杀软隔离）。
2. 再确认 `logs\scripthook.log` 是否存在：
   - **不存在** → DLL 没被加载 = 文件位置不对或被隔离（第 2.1 / 2.2 节）；
   - **存在但不是 8 行 `loading plugin`** → 把该文件发回来。
3. 顺带看一下游戏根目录有没有多出 `scripthook.log`（说明 `logs\` 不可写，走了退路，见第 5 节第 6 项）。

## 8. 卸载与回滚

**卸载（删三个东西就干净了）：**

1. 关闭游戏。
2. 删除游戏根目录下的 `dinput8.dll`、`scripthook.ini`、`plugins\`。
3. 残留目录按需处理：
   - `logs\` —— 日志，可直接删；
   - `mods\` —— 你自己的 mod，与框架无关；
   - `plugins_off\<时间戳>\` —— 只有跑过开发构建才会有，里面是被移出公测集的插件（**是移走不是删除**）。
4. 删完启动游戏，行为与未装框架时一致。

**回滚到上一版**：本测试包是**全新安装**，删掉即是回滚。若以后在同一台机器上覆盖升级，
请在开发机构建时用 `-BackupDir` 备份（默认关闭），或自行保留一份 `dinput8.dll` + `plugins\`。
