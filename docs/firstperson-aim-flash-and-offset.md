# 第一人称：开镜闪屏的根因与修法，以及瞄准偏移的调查（2026-09-29）

本篇记两件事：**开镜闪屏**（已解决）与**瞄准时准星/消音器偏移**（机理查清、未解决，且已证明"单一常量修不了"）。
所有结论都带实测证据；地址配方见文末，可在任意会话复算。

## 一、开镜闪屏：根因与修法（已解决）

### 根因

不是 beta3/beta4 引入的玄学，而是**按下开镜那一帧，整帧相机被交给引擎**：

```c
/* 旧行为（等价于社区表）：引擎自己的 ADS 字节一竖起来，整帧让位 */
if (g_fp.skip[3]) { g_bow = BOW_ADS; return 0; }
```

`g_fp.skip[3]` 是引擎自己写在 ADS 两个站点上的字节（`S_ADS_IN 0x147FF669` / `S_ADS_OUT 0x147FF653`）。
让位那一帧，画面从"我们的眼位"切到"引擎当时那台相机"——腰射时引擎相机在**我们身后 1873 mm**（第三人称），
于是**一帧跳 1.87 m**，这就是闪。

### 修法（`scripthook_fpx.c`）

```c
if (g_aimHold > 0 && g_fp.skip[3]) { g_bow = BOW_ADS; return 0; }
```

默认 `g_aimHold = -1` → **不交还**。帧永远归我们，瞄准两端都没有切换，闪**在结构上不存在**（不是靠阈值挡）。

### 实机证据（用户确认"闪完全没了"）

| 判据 | 交还版 | 保底版 |
| --- | --- | --- |
| `scripthook_fpx.log` 里 `engine's camera jumped … (last frame was ads)` | 10 条（1 秒 1 条） | **0 条** |
| `the eye jumped` | 有 | **0 条** |
| 瞄准中的 `meas:` 心跳 | 会写出让位 | `raw=1 gate=1 hold=-1 fov=0.4916 **bow=0**`（= 仍是我们在放眼位） |
| 残余的引擎相机跳变 | —— | 11 条，全部标注 `last frame was menu`（菜单↔世界，正常） |

**A/B 一条命令可复现**：`shcall ShFp2AimHold i 1` → 闪立刻回来；`i 0` → 又没了。

> 顺带发现：用户那把武器瞄准时 `fov = 0.4916`，**低于旧版"倍镜阈值 0.5"**——旧版那种"按 fov 交还"的写法
> 会在它每次开镜时都交还一次，是**另一条独立的闪源**，现在这条路径已不在代码里。

## 二、瞄准偏移：机理、实测、排除项（未解决）

### 现象

手枪（机瞄+消音器）开镜后，准星/消音器**偏向一侧**，且**换肩（中键）后仍偏同一侧**；
步枪消音器与手枪的需求**不一致**（调好手枪，步枪又歪）→ **偏移是每把枪不同的**。

### 机理（由 A/B 与 191 mm 实测确定）

- **交还打开**（画面 = 引擎自己的瞄准相机）：准星**完全正**。
- **保底**（画面 = 我们的眼位）：偏，且**偏移量 ≡ 我们眼位与"引擎瞄准架"之差 = 191 mm**
  （两次独立测量 190 / 191 mm；腰射时该差值为 1873 mm，因为引擎还在第三人称位）。
- 结论：**武器与瞄具是照"引擎瞄准架"（肩 + 枪的位姿）摆的**，那个架在瞄准路径里按角色姿态算出来；
  交还时画面**就是**那个架 → 准；保底时画面是我们的眼 → 差 191 mm。

### 排除项（全部实测，写在这里省下重走）

| 候选 | 做法 | 结果 |
| --- | --- | --- |
| `cm+0x170`（管理器位置） | 我们每帧写眼位（现行为） | 偏移照旧 ✗ |
| `cm+0x190` 矩阵块 | 我们本来就写 | 偏移照旧 ✗ |
| `cm+0x1E0` 第二份相机副本（离眼 0.386 m，仅单轴错开） | 每帧写眼位，连续 18 秒（`ShCameraAltEye`） | **无变化** ✗ |
| `xmm2`（相机存储指令处引擎寄存器里的值） | 桩内 `movaps xmm2,[rax]` 覆盖，持续 12 秒 | **无变化** ✗ |
| 尝试"擦身接手"（`ADOPT_M/STAY_M`） | 在引擎 ADS 过渡经过眼位时交接 | 无变化 ✗（原因见下） |
| 全局常量偏移（`g_aimRig` 三分量） | 实测标定后写入框架，按 fov 进度缩放 | 手枪小一点、步枪更歪 ✗ → **单一常量不可行** |

**"擦身接手"为什么无效**：保底模式下我们**每帧写 `cm+0x170`**、且引擎在瞄准时会**跳过它自己的头部/位置计算**，
所以 `cm+0x170` 里读到的是**我们自己的值** → 判据 `|引擎 − 我们| = 0` → 接手等于没接（幸好也没闪，因为没有切换）。

**由此得到的硬结论**：保底模式下，**引擎那台"瞄准架"不落在任何可读的字段里**（引擎不计算它）；
它对武器/瞄具的定位**不受帧侧任何写入影响**。

### 未走通的路（留给以后）

1. **让引擎按我们的相机摆枪**：需要在瞄准路径里拦截其姿态计算。今天顺着站点追过：
   `S_ADS 站点 → 我们的桩（0x18620000/0x18630000）→ 0x26657C0 → 构造函数 0x1329FC70`；
   但该区域**大量函数是 5 字节 `jmp`+`CC` 跳板**（反篡改/混淆的典型形态），
   逐跳跟随成本高，且**尚未找到"算瞄准架"的那一跳**。
2. **按武器分类的多套偏移**：可行但工程量与维护成本高（每把枪都要标定），
   而 `ShFp2SetOffset` 已有"按载具类别分组"的先例，可作为实现参考。

### 相关但独立的一条线索（已排除）

`FN_VIS 0x2A257C0` 在当前构建上是**跳板**，本体 = `0x148B32C0`
（`cmp [rcx+68h], dl`，真·可见性函数；`dl` 就是可见性状态）→ 框架直接调用它是**有效**的，
之前的"地址不一致"疑虑作废。

## 三、可复用的现场工具与配方

### 1) 代码基址自证（不靠猜）

```
日志 scripthook_camera.log 中：
  manager store: <XXXX> is the store, left alone (the fallback)
此处 7 字节必为 0F 29 90 70 01 00 00（movaps [rax+170],xmm2）
→ 基址 = XXXX − 0x81E0B77
→ 管理器全局 = XXXX − 0x3625847         （即 0x81E0B77 处 mov rax,[rip+disp] 的目标）
→ 读该全局 8 字节 = 管理器对象
→ 引擎相机（交还时）= 管理器 + 0x170 ；我们的眼位（保底）= 管理器 + 0x170
```

### 2) 识别"我们自己的桩"

ADS 站点被我们改指到桩，桩的字节形状固定（`InstallAds` 发射的序列）：

```
50                       push rax
48 B8 <imm64>             mov rax, &g_fp.skip[3]
88 10                     mov [rax], dl
48 B8 <imm64> … 88 10     第二次（own 字节）
…  58                    pop rax
E9 <rel32>               jmp <真正的原函数>
```

**推论**：若某"调用目标"读出这段字节，它不是引擎函数，而是我们的桩；
其尾部 `E9` 的 rel32 才是真正的被调者（`目标 = 桩尾下一条指令 + rel32`）。

### 3) 定向值匹配（找"离 X 若干距离的坐标"）

用工作台的 `read`（默认 128 字节，**小窗口**）逐段读候选对象，按三连 float 与参考点求距离筛选。
`+0x1E0`（离眼 0.386 m、单轴错开）就是这样找到的。**不要用 `scanvec3` / `scanfloat`**
（全内存扫描，实测 5 秒即被丢弃，且曾导致游戏崩溃）。

### 4) 两个"别用"的教训

- `rd` 在 PowerShell 里是 `Remove-Item` 的别名，**别名优先级高于同名函数**——脚本里别叫 `RD`。
- `read` 的输出解析要**跳过前导空串**（`-split '\s+'` 会产生），否则逐字节循环会提前 break。

## 五、2026-09-30：瞄准架（学习/贴合）、切枪首镜残影、以及一处已知取舍

### 1) 落地的行为

- **保底**：`scripthook_fpx.c` 的让位分支加 `g_aimHold > 0` 前置，**默认 `-1`** 即"**只在瞄准到位后交还**"
  （`g_aimHold 0` = 从不交还，`1` = 从按下就交还）。闪屏按此消除，得到实机确认。
- **瞄准架**（`scripthook_camera.c` 的 `MgrCallback`）：按"**稳定后的 fov**"分槽（一把武器一个槽），
  在引擎拿帧的帧上量"眼位→引擎座椅"向量，在**我们自己拿帧的帧**上把眼位**限速贴过去**：
  - 只发布**键与当前 fov 相符**的槽（防切枪时贴上别枪的值）；
  - **限速 40 mm/帧**（≈0.12 s 走完 255 mm，读起来像准星抬起，不是切一下）；
  - 样本 > 400 mm 直接丢弃（只有槽自身越界才清零）；
  - 只让"本次开镜以来的最低 fov"教学。

### 2) 实测数字（都是日志/探针原值）

| 项 | 值 |
| --- | --- |
| 手枪机瞄 fov / 座椅 | `0.6882` / 眼**前**约 `181~190 mm` |
| 步枪 4x fov / 座椅 | `0.4916` / 眼**后**约 `255~274 mm` |
| 另一支倍镜 fov | `0.4048` |
| 腰射时引擎相机与眼 | `1873 mm`（第三人称机位） |

### 3) 今天被日志**排除**的假设

- `manager +0x120`：普通开镜**始终为 0**，从不写入。
- `manager +0x1E0`（离眼 0.386 m、单轴错开）：每帧写它 6 秒 + 两段 18 秒，**画面无变化**。
- 视图对象（`+0x158 -> +0x30`）与 `+0x170`、`+0x1C0`：**逐字等于我们的眼位** → 位置链跟着我们走。
- 因此**引擎的对齐不读任何"存下来的副本"**，而是用它**当场算出的相机**。

### 4) 切枪首镜残影（当前已知取舍）

复现：手枪开镜 → 切步枪 → **第一次**开镜，画面右侧"镜片/残影"贴脸一次；第二次起正常。

- 幽灵那几帧 `rig probe` 里 `lastEye` **逐毫米不变** → **不是我们在移动相机**。
- 机制：引擎的枪/镜模型画在**它自己的座椅**上（步枪离眼 255 mm），我们的相机在座椅前方 →
  **第一次抬枪时模型穿过相机**。
- 为何只有第一镜：那个 255 mm 只有"引擎拿帧"时才量得到，而保底之下这种帧出现在**到位附近** →
  第一镜量到它时模型**已经穿过**；第二次起槽里已有值，故正常。
- **近裁剪面是一处三明治**（今日实测）：`CAM_NEAR_FP 0.02f` 恒定 = **不闪但在开镜段多画出贴脸几何**；
  改回"只在我们真的写了眼位的帧才拉近"= **贴脸消失但闪屏回归**
  （11:11 实测 → 11:15 撤回）。**不要再在这上面二选一**。

### 5) 未做但已定位的下一步（若要做）

`scripthook_fpx.c` **每帧都已经算出引擎瞄准相机的坐标**（`g_lastGapMm` 就是用它减眼位算出来的，
出处 `scripthook_fpx.c:229-240`，现被标注"只读、绝不可用于决策"）。把它导出（如
`ShFp2EngineCam(float *out)`），由相机模块在**抬枪过程中限速把眼位靠向它** →
第一镜也落在座椅上 → **贴脸消失且不动近裁剪面** → **不会闪**。这是唯一已知能同时满足两者的路。
