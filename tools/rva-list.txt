# Old engine addresses, by the name the framework source uses.
#
# This is the checklist for the next game patch. Every constant the framework
# pins is here with the address it carried BEFORE the update it survived, so
# the next update can be mapped the same way it was last time:
#
#   pwsh tools/grw-relocate.ps1 -Cmd batch -Pattern tools/rva-list.txt
#
# The tool reads the first hex token after each name, so that one is always
# the OLD address; everything after it is a note for a human.
#
# Read the answer by the kind of entry:
#
#   function  a .pdata body: the tool answers with an address and a body
#             match percentage. 90%+ with a single candidate is a pin.
#   interior  a site INSIDE a body (a byte pattern the running code matches,
#             like the blur and fov sites). The tool can only say "near X".
#             Pin those by comparing the bytes around the site, not by
#             trusting its number.
#   thunk     a bare E9 jmp: -Cmd thunk or -Cmd jumps answers, not batch.
#   data      a global. The tool CANNOT answer ("neighbourhood only" is
#             noise, and several unrelated slots all report the same one).
#             Two methods do work:
#               * decode the engine's own call sites: a mov rcx,[rip+disp32]
#                 right before the call gives (next insn + disp32). Two
#                 independent call sites must agree, and decoding the OLD
#                 build the same way must give the old value in this list.
#                 That cross-check is what makes it trustworthy.
#               * compare structure across builds when the engine reads the
#                 data rather than calling code: a vtable's entries in order,
#                 or a descriptor's tail bytes.
#
# The "how" column is the point of this file, and so is saying when there is
# none. A constant that was never confirmed in game says so: that is the most
# useful line here, because it is the one that breaks silently next time.
#
# The rule this file exists for: a stale constant does not fail loudly. It
# calls the wrong code or reads the wrong slot, and the symptom surfaces in a
# plugin nobody connects to it. RVA_PLAYER_MGR lived in api.c and entity.c,
# only one copy was re-pinned, and every entity search went silently empty.
# Anchors that exist in more than one file are the ones to grep for by value,
# not by name.
